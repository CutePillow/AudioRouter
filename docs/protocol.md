# AudioRouter 音频协议 v1

## 当前范围

第一版只传输播放音频，不包含麦克风和虚拟音频设备。当前传输层使用局域网 TCP，Bluetooth Classic 不绑定协议格式，后续可复用同一套帧结构。

## 音频参数

- 编码：支持 PCM 16-bit little-endian 和 Opus；具体使用哪一种由握手能力和本地偏好决定
- 采样率：48 kHz
- 声道：单声道或立体声
- 建议帧长：20 ms
- 单个数据包最大负载：64 KiB
- 字节序：小端

## 音频包布局

| 偏移 | 长度 | 字段 |
| ---: | ---: | --- |
| 0 | 4 | Magic，固定为 `ARAU` |
| 4 | 1 | 协议版本，当前为 `1` |
| 5 | 1 | 包类型，音频为 `1` |
| 6 | 1 | Flags，当前保留为 `0` |
| 7 | 1 | 保留字段 |
| 8 | 8 | 会话 ID |
| 16 | 4 | 音频序号 |
| 20 | 8 | 时间戳，单位为毫秒 |
| 28 | 4 | 采样率 |
| 32 | 1 | 声道数 |
| 33 | 1 | 编码类型，Opus 为 `1`，PCM 16-bit 为 `2` |
| 34 | 2 | 保留字段 |
| 36 | 4 | 负载长度 |
| 40 | N | 按编码类型解释的音频负载 |

## 编码类型

- `1`：Opus
- `2`：PCM 16-bit little-endian

## 控制消息

控制消息作为 `Hello` 或 `HelloAck` 帧的负载传输，负载格式为：

| 偏移 | 长度 | 字段 |
| ---: | ---: | --- |
| 0 | 1 | 控制协议版本，当前为 `1` |
| 1 | 1 | 消息类型 |

消息类型：

- `1`：Hello，后接设备 ID、UTF-8 设备名和能力位
- `2`：HelloAck，字段同 Hello
- `3`：设置发送开关，后接 `0` 或 `1`
- `4`：设置接收开关，后接 `0` 或 `1`
- `5`：设置发送音量，后接 `0–100`；0 为静音，100 为原始音量
- `6`：设置接收音量，后接 `0–100`；0 为静音，100 为原始音量
- `7`：Ping，后接 u64 值
- `8`：Pong，后接 u64 值

### 能力位

Hello/HelloAck 的设备名之后附带一个小端 u32 能力字段：

- bit `0`：支持 PCM 16-bit
- bit `2`：支持 Opus
- bit `8..9`：编码偏好，`0` 自动、`1` Opus、`2` PCM
- bit `10..19`：Opus 目标码率，单位 kb/s，范围 `6..450`

Android 的局域网设置使用 Opus 压缩或 PCM 未压缩；压缩模式当前提供 `32/64/96/128/192/256/450 kb/s`。旧客户端未声明 Opus 能力时自动回退 PCM。

Android 开启音频采集或已有局域网/蓝牙设备连接时，锁定“音频传输”和“音频缓冲”设置。两项调暗，点击提示“请关闭传输后再调整设置”，服务层同时拒绝修改，避免重新配置中断连接。停止采集并断开全部设备后恢复可调整；仅开启设备发现不会锁定，外观和个性化设置不受影响。

## 控制包类型

协议已经预留以下包类型：

- `1`：音频
- `2`：Hello
- `3`：HelloAck
- `4`：Ping
- `5`：Pong

控制消息负载格式与传输层无关。音频层必须拒绝未知版本、未知包类型、错误长度和超大负载，避免连接错误导致内存异常。

音量滑块使用 -60 dB 到 0 dB 的对数增益曲线；0 是静音，100 是单位增益，不提供高于原始信号的放大。

## 局域网 TCP

- 默认监听端口：`40400`
- 客户端先发送 Hello 帧
- 服务端回复 HelloAck 帧
- TCP 负责控制消息和音频帧的有序传输
- Android 端采集 48 kHz、立体声、PCM 16-bit 音频，按左右声道交错保存，每个 20 ms 帧为 3840 字节；PCM 模式跟随源设备或选择双声道时保留左右声道（1536 kb/s），选择单声道时混合左右声道（768 kb/s）；Opus 使用 20 ms 双声道帧，总码率由传输设置决定
- Windows 端 Loopback 输出 48 kHz、立体声、PCM 16-bit 音频，每帧约 20 ms；Opus 模式使用握手中的目标码率

## Bluetooth Classic 服务

Bluetooth Classic RFCOMM 使用以下自定义服务 UUID：

b5c9f1b4-7a9c-4c0e-9e3c-4e4f9b2f7d01

Hello 包使用类型 1，HelloAck 使用类型 2，负载是 UTF-8 客户端标识和能力位，例如 AudioRouter Android 16。连接建立后，接收端应先读取完整的 40 字节头部，再按照头部偏移 36 的小端 u32 读取负载长度；流式读取不得假设一次 read 就能得到完整数据包。

Bluetooth Classic RFCOMM 复用同一套帧结构。Android 设置提供自动、Opus、PCM 三种协议偏好。Android 只使用系统播放音频捕获，不请求麦克风权限。
